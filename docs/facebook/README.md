## 公開の扱い

主投稿JSONから投稿単位の公開範囲を確認できなかったため、128件すべてを非公開の本人確認待ちとしました。公開承認済みは0件です。アカウントの既定設定から過去投稿の公開範囲を推定しません。

- メッセージとその添付、連絡先、友人関係、ログイン・位置履歴等は公開候補から除外します。
- 投稿本文・写真の家族や友人の名前、顔、タグ、所属、住所、健康情報、会話、子どもの情報、勤務先情報を個別確認します。タグなしでも第三者情報がないとは限りません。
- 本人が今回の掲載内容を確認・承認したものだけ編集対象にします。第三者について必要な許諾を確認するか、削除・匿名化・写真差し替えを行います。
- 投稿関連JSONにはupload_ipやEXIFの構造があります。原JSON・原写真を直接配信せず、公開用画像の位置情報等を除去・確認し、原本は別保管します。

原本ZIP、全件台帳、内部パス一覧、投稿本文、画像・動画、メッセージ、連絡先、認証関連情報はこのPRに追加していません。非公開の台帳はローカルに保管します。下書きでもPRやリポジトリの閲覧者には読めるため、これらをGit管理へ入れません。

## Writingと人生年表への統合

既存のWordPress整理資料と[Evernoteの確認用下書き](../evernote/README.md)を土台にします。NotionとGoogleフォトの実データは今回未調査で、以下は統合設計の提案です。

| 情報源 | 役割 |
|---|---|
| WordPress | まとまった既存記事をWritingの軸にする |
| Evernote | 発想・当時のメモから本人の体験と背景を補う。引用・外部資料は分離 |
| Facebook | 承認済みの当時の発信と投稿日時を照合資料にする |
| Notion | エクスポート確認後、完成稿・整理資料・私的情報を分類する |
| Googleフォト | 実データと同意を確認後、写真原本と撮影情報の補助証拠に使う |

まず2013〜2014年のFacebook104件とEvernoteを照合し、同じ経験のメモ・投稿・写真を束ねます。具体的な記事テーマは本文確認後に決めます。Writingは一つの体験や考えを読める記事に整え、当時の文章と現在の追記を区別します。元の記録日と今回の公開日を別に持ちます。

人生年表には投稿をすべて並べず、節目となる出来事を短く記載し、Writingへリンクします。既存項目がある場合は根拠を追加し、重複項目を作りません。投稿日だけで出来事の日を断定せず、日付の確度を保持します。

同文のWordPress記事・Facebook投稿は一つの記事に統合し、出典は非公開台帳に残します。写真はハッシュ一致を優先し、圧縮・リサイズ版は撮影情報や見た目を照合して本人確認します。同じ日というだけで同一の出来事にまとめません。

非公開台帳には統合ID、情報源・原本への参照、投稿日時、出来事の日と確度、関連写真、既存記事・年表ID、第三者情報の確認結果、公開範囲、本人承認日、公開用本文、公開状態を持たせます。承認済みの公開用データだけサイトへ渡す運用にします。
